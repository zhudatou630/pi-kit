# Skill Creator

用户的 skill 主要是工作流描述：一件反复做的事为了什么、怎么做、做成什么样。目标是帮用户把它聊清楚，写成一份短而准的 SKILL.md。

## 1. 先聊清楚

用对话弄清下面几件事，每轮最多问 2–3 个问题；用户卡住时，先按已有信息猜一版让他改。

- **目的**：用户真正想达成什么效果；硬要求是哪一两条。
- **输入和产出**：平时给什么材料，交回什么、放在哪。
- **怎么做**：关键步骤，哪些地方需要判断、需要停下来问用户。
- **出错的代价**：个人用还是交给别人；错了能不能重做，用户能不能自己发现。

如果这件事不是反复出现的工作流，直接说：常驻规则进 `AGENTS.md`，确定性操作写成脚本，一次性的直接回答。

## 2. 写 SKILL.md

frontmatter：

```yaml
---
disable-model-invocation: true   # 用户手动调用的工作流默认加；需要 AI 自动识别时才去掉
name: skill-name
description: 一两句：什么时候用、产出什么。容易和别的 skill 混淆时，加一句"不是 xxx（`other-skill`）"。
---
```

正文只有三块：

1. **目的段**（几行）：为了什么、硬要求、出错代价；规则没覆盖到的情况按硬要求取舍。
2. **怎么做**：按步骤写工作流，包括输入在哪、产出放哪、哪里停下来等用户。
3. **资源**（有才写）：`references/` 放长模板、范例、只在部分情况用到的细则；`scripts/` 放确定性、易错的重复操作。每个文件写明做什么、什么时候读或跑。

## 3. 严格程度按出错代价定

| 情形 | 写法 |
|---|---|
| 个人用、能重做、错了自己能发现 | 写原则和做法，不要求记录、不要求逐项汇报；只告诉用户需要他做决定的事 |
| 产物交给别人、涉及合规 | 少数几条硬约束；能用脚本校验的交给脚本，不写成文字自查清单 |
| 有外部副作用或不可逆（发消息、删文件、动账号） | 在那一步设硬停点，等用户确认 |

## 4. 写完自查

- **删掉没作用的话**：去掉这一行，AI 默认也会这么做吗？会就删。
- **说要做什么**：写目标行为（"每段不超过 3 句"），少写禁令（"不要啰嗦"）。
- **一件事只说一处**：同一条规则出现两次，合成一处。
- **太长就拆**：只有部分情况才用的细则，移到 `references/`。

然后跑格式校验：`python3 scripts/validate_pi_skill.py /path/to/skill`
